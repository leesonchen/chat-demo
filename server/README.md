# Chat Demo account and cloud backup service

The optional backend uses Node.js built-ins, including `node:sqlite`. It does not proxy DeepSeek chat requests. The browser continues to call the configured DeepSeek API directly.

## WeChat preparation

1. Use a verified WeChat Official Account (service account) and set your HTTPS site hostname as its Web Authorization Domain.
2. Serve the account's verification file at the site root if WeChat requires domain verification.

Webpage OAuth uses the site's `/api/auth/wechat/callback` route. The Official Account's message-push settings are independent of this callback.

## Configure the backend

Copy `server/.env.example` to `server/.env` and set:

- `APP_ORIGIN=https://chat.example.com`
- `WECHAT_APP_ID` to your Official Account AppID.
- `WECHAT_APP_SECRET` to the existing Official Account AppSecret.
- `WECHAT_REDIRECT_URI=https://chat.example.com/api/auth/wechat/callback`
- `API_KEY_ENCRYPTION_KEY` to a 32-byte key generated by `openssl rand -base64 32`.
- `DATA_DIR` to a persistent directory.

Keep `server/.env`, the database, and backup files out of Git. Back up `API_KEY_ENCRYPTION_KEY` separately; losing it makes stored API keys unrecoverable.

## Run and reverse proxy

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm server
```

The API listens on `127.0.0.1:8091`. Configure Nginx/Caddy to serve `dist/` on your site hostname and proxy `/api/` to `127.0.0.1:8091`. Keep the Node service bound to loopback and use HTTPS in production.

## QR login

1. Open WeChat sign-in, optionally opt in to showing your WeChat name and photo, and generate the QR code.
2. The frontend renders a QR code containing the WeChat Official Account OAuth URL.
3. Scan the code in WeChat. The default `snsapi_base` scope provides the OpenID. Opting in requests `snsapi_userinfo`, so WeChat can authorize profile access.
4. The computer polls with a separate one-time ticket and secret to claim its own HttpOnly login cookie.

The QR state, browser polling ticket, and polling secret are distinct. The transaction expires after ten minutes and can only be claimed once. Chat Demo stores a nickname and avatar URL only after the user opts in and WeChat grants profile access. Subsequent basic sign-ins preserve an already authorized profile and resolve to the same account.

## Data and behavior

- SQLite database: `DATA_DIR/chat-demo.sqlite`.
- Cloud backups: `DATA_DIR/backups/`, one ZIP snapshot per user. A new export replaces that user's previous snapshot.
- Restoring a cloud backup replaces the current device's local history; it does not merge histories.
- The ZIP retains all conversation branches and locally available image originals. Other attachment types retain metadata only, matching the existing local ZIP behavior.
- API keys are encrypted at rest with AES-256-GCM. After login, the browser retrieves its own decrypted key over the authenticated HTTPS session so the existing direct-to-DeepSeek client continues to work.
- The provider-based identity table leaves room for a future QQ identity. QQ login, automatic sync, real-time multi-device collaboration, and conflict merging are not included in this phase.

Back up the SQLite database and the `backups` directory together. Back up the encryption key separately and securely.
